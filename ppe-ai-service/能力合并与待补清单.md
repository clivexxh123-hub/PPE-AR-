- 增加 GitHub Actions：在 PR 和 main 推送时执行 Python 3.12 mock 回归。

## 二、暂未合并的内容

### `human_wearing` 人物佩戴生成

未拿入 PR #5 的以下提交：

- `b4162ea`：Add human wearing generation mode to AI tasks
- `9df5409`：Use low denoise for human wearing generation

未合并原因：

1. 当前实现主要是把透明 PPE 图片按固定相对位置贴到人物参考图，再用 SD1.5 低 denoise 图生图；没有人体关键点、部位检测、遮挡关系或真实佩戴约束。
2. 已说明的真实样例只覆盖 3 个安全帽样例，不能外推到护目镜、面罩、手套、反光背心、防护服等 PPE 品类。
3. 本次环境没有运行 ComfyUI，无法独立复验真实出图、模型版本、工作流和结果素材。
4. `denoise=0.15` 是固定经验值，缺少按品类、输入质量和目标效果的配置及回归矩阵。
5. 缺少可重复检查的真实输入、输出样例和人工验收记录。

建议达到以下条件后再单独合并：

- 至少完成安全帽、护目镜/面罩、反光背心三个不同佩戴部位的真实样例验证。
- 每个品类保留可复现的输入、工作流版本、模型版本、参数、输出图和人工验收结论。
- 对位置、比例、遮挡、产品结构保持、人物畸形设置明确失败条件。
- `human_wearing` 有独立自动化回归，并加入统一 CI，而不是只保存一个未执行的 smoke 脚本。

## 三、已经拿入、但仍缺线上环境验证的内容

以下代码已合并，是为了先让业务端和 AI 服务可以继续开发；它们不能被描述为“生产环境已验收”：

### OSS 预签名上传

仍缺：

- 真实 OSS bucket、预签名 URL、过期 URL、必需 headers 的在线验证。
- 成功、403/签名过期、429、5xx、超时和断网的完整记录。
- 大图上传的内存和超时指标。

### callback

仍缺：

- 真实业务任务中心接收 `running/succeeded/failed` 事件的联调。
- 重复投递、超时、业务端 4xx/5xx、幂等和重试策略。
- callback 目标域名白名单或服务级网络出口策略。

### ComfyUI 图生图

仍缺：

- 固定并记录 checkpoint、ComfyUI 版本、工作流 JSON 版本和 GPU 环境。
- 用真实产品图验证输入上传、节点 ID、denoise、输出文件和超时行为。

## 四、仍保留的已知限制

- `logo_remove_bg` 是 Pillow 简单背景算法，不适用于复杂纹理、阴影、渐变、毛发边缘和半透明材质。
- `print_render` 是二维平面合成，不处理透视、曲面贴合、真实光照或实际印刷尺寸。
- URL 的应用层校验不能完全消除 DNS rebinding；生产部署还应限制 AI 服务的网络出口。
- `local_path` 仅用于可信本地开发环境。对外部署时应关闭或在网关/业务层禁止客户端传入任意服务器本地路径。
- 未提供 `output` 且存储后端为 local/mock 时，任务会以本地结果完成；生产环境应强制业务端提供 OSS 输出配置。

## 五、当前建议启动方式

1. 先以 `AI_ENGINE=mock` 跑通业务端 `/ai/tasks`、任务状态、Logo、print_render、结果 metadata 和异步生命周期。
2. 再启动真实 ComfyUI，单独验证文生图和图生图。
3. 最后接真实 OSS 与 callback；完成本文件第三部分的在线验证后，再标记为生产可用。

本次合并的目标是先提供稳定的开发和联调底座，同时把尚未验证的能力明确隔离，避免把“已拿入代码”误写成“所有能力已完成”。
